## 一、问题阐述与分析

### 1. 问题背景

威海高校校区距离威海机场较远、公共交通不便，学生前往机场打车费用高，拼车是普遍刚需。目前此类需求主要通过微信群、表白墙等渠道零散发布，存在明显痛点：

- **信息分散、时效性差**：消息易沉底，凑车靠运气；
- **无结构化匹配**：时间窗、人数、性别等条件靠人工逐一比对；
- **安全顾虑**：部分同学倾向与同性拼车，人工撮合难以保证；
- **拼不满**：车辆利用率低，人均出行成本高。

本项目构建一个**机场拼车匹配工具**：拼车者提交人数（1-4 人）、出发时间段、性别与性别偏好，后端将时间窗有交集的拼车者组合成团（每车最多 4 人），以"**把车拼满**"为优化目标。题目核心不是常规的信息管理（CRUD），而是**匹配算法与数据结构的设计**，符合课程设计对数据结构与算法应用的考核要求。

### 2. 应用意义

1. **实用价值**：通过"人数 + 时间窗 + 性别偏好"的结构化匹配，把分散需求聚合成满载车辆，降低人均出行成本、提高车辆利用率、减少空驶。
2. **安全价值**：性别偏好机制（可偏向任意性别）将安全顾虑显式纳入匹配约束，由程序保证"偏好不满足不成团"。
3. **教学价值**：完整覆盖时间桶、优先队列、扫描线等数据结构与贪心、匈牙利匹配、近似算法分析等算法内容，是"数据结构 + 算法"的综合工程落地，区别于以数据库 CRUD 为主的常见课设。
4. **演示价值**：管理台 GUI + 虚拟乘客流可一键演示完整匹配链路（生成 → 匹配 → 提案 → 同意/拒绝 → 成团 → 完成），适合中期检查与验收答辩。

### 3. 主要问题

本课题可建模为**带时间窗、容量与性别偏好约束的实时成团问题**。主要难点：

1. **实时性与动态性**：乘客随时注册、修改、取消，匹配引擎须支持增量更新（插入/删除/改窗 O(1) 级操作），不能每次全量重算。
2. **三重约束耦合的可行性判定**：同车须同时满足时间窗重叠、人数不超过 4、性别偏好双向满足；冲突偏好（互相要求对方性别）必须判定为不可行。
3. **最优性与实时性的矛盾**：将乘客最优分组为满载车辆是 NP-hard 问题（可归约为装箱问题），在线场景下只能先用贪心近似保证实时可用，再以批次全局优化提升解质量。
4. **提案状态管理**：匹配结果以"提案"形式呈现，须完整处理同意/拒绝/超时/取消/改时间的状态转移，并保证多请求并发下的一致性（单锁串行化）。
5. **可演示性与可验证性**：教学模拟项目须可一键演示、可用虚拟乘客流复现场景，且算法行为可测试（确定性输入、固定随机种子）。

### 4. 计划实施方案

1. **总体架构**：前后端分离。后端 C++17 + CMake + cpp-httplib + nlohmann/json，监听 127.0.0.1:8080；前端 Vue 3 + Vite 管理台，经 dev proxy 访问 `/api`；HTTP/JSON 通信，统一响应信封 `{code, message, data}`。
2. **后端分层**：HTTP 路由层 → Service 门面（单锁串行，杜绝竞态）→ 状态机 / 匹配引擎 → 索引数据结构（时间桶 / 扫描线 / 优先队列）→ 事件日志。超时与自动行为统一由 `tick(now_ms)` 驱动，测试注入假时钟，不依赖真实等待。
3. **算法阶梯路线**：主线为**在线贪心匹配**（时间桶取候选 + 紧急度堆选种子 + 贪心填充），保证任意时刻可触发一轮匹配；P4 阶段实现**批次全局优化**（n≤50 枚举可行 4 人组 + 匈牙利最大权匹配，n>50 回退贪心），并以固定种子实验对比两档解质量。
4. **系统形态**：管理台 GUI（总控台 / 匹配池 / 成团 / 事件流四视图）+ 虚拟乘客流（定时生成、自动同意提案、按概率拒绝以演示重匹配），提供一键演示脚本。
5. **开发流程**：git 分支协作（a/*、b/*）+ PR 评审 + GitHub Actions CI（构建 / 单测 / 格式 / 前端构建，P2 起端到端 smoke）+ clang-format 统一格式；接口契约文档（contract.md + 机器可读 contract.yaml）为唯一事实源，P1 末冻结 v1。

### 5. 拟采用的数据结构与算法

**数据结构**（基于 C++ 标准库实现）：

| 数据结构 | 用途 | 关键操作与复杂度 |
| --- | --- | --- |
| 时间桶（TimeBucketIndex，10 分钟粒度 144 桶） | 乘客按 start_min 分桶索引 | 插入 / 删除 O(1)；窗口候选查询 O(桶数 + 输出) |
| std::multiset 扫描线 | 维护按 start_min 有序的活跃乘客集合 | 取时间窗重叠邻居 O(log n + k) |
| priority_queue（紧急度堆） | 种子选择：人数多者、出发早者优先 | O(log n) |
| priority_queue（超时堆） | 提案 TTL 到期检测 | 只弹队首 O(log n) |
| std::vector + 自增 event_id | 事件日志，前端 since_id 增量轮询 | 追加 O(1)、查询 O(k) |
| 假时钟注入 | 状态机 / 超时逻辑可测试性 | —— |

**算法**：

| 算法 | 用途 | 要点 |
| --- | --- | --- |
| 在线贪心匹配 | 主线匹配引擎 | 种子选择 + 按人数降序贪心填充至 4 人；n=500 时一轮 < 200ms |
| 一维 Helly 性质 | 同车时间窗判定 | 区间两两相交 ⇒ 全体相交，只需 max(start) ≤ min(end)，O(1) |
| 性别偏好约束检查 | 可行性过滤 | 团 ≤ 4 人，朴素重验成本可忽略；冲突偏好判不可行 |
| 匈牙利最大权匹配（P4） | 批次全局优化 | 枚举全部可行 4 人组后求最大权匹配（权重 = 拼满度 + 等待收益 − 性别惩罚） |
| FFD 近似比分析 | 理论章节 | 解释贪心不能保证最优；装箱 NP-hard 归约论证 |
| Gale-Shapley 稳定匹配思想（P4） | 理论章节 | 借鉴稳定性概念；说明拼车为非二分图（稳定舍友问题），改造其偏好约束思想 |
